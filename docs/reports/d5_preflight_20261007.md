# D5 开跑前实现验收

本轮实现了隔离的五组在线入口和 W 事件缓存加速，默认 F6 没有启用研究算子。原 D4 文件和协议保持原样。正式设计见 [D5 协议](../experiments/d5_online_eight_hour.md)，480 次新实例实验尚须双 Python CI 与两节点同时 pilot 验收后才能派发。

W 的缓存只存活于一个插入步骤。它保留全部原积分断点、实例求和顺序及窗口积分顺序，省去每个位置反复建立活动区间与逐区间扫描。窗口评分逐位相等，因此并列选择和随机流未变。G+W 是新增的独立实验组；并未采用在线状态门控。

8 个旧 development base 的 288 组冷调用配对：原 W 15.34375 CPU 秒，加速 W 12.25 CPU 秒，G+W 11.015625 CPU 秒；W 整个构造的总 CPU 减少 20.16%，加速比1.253。全部配对候选、attempts 和 RNG 状态相同，并复验了源及候选 exact 可行性。这是工程 benchmark，不是在线 HV 收益。

本地完整门禁：420 tests 通过，lint/format/mypy 通过，overall coverage 84.76%、core 96.71%。新增55项检查涵盖固定尾窗、缺失 Decode、重叠活动、空区域、逐位窗口、完整池与RNG、组合证书、默认 engine轨迹、五组事务导出/最终exact/篡改拒绝及矩阵同源输入。deterministic replay 为 `aeb9824d2e671fe76771297ece91af40576124c930721193c18127cbdb814fa7`，与改动前相同；D03发布验证、wheel build、CLI smoke通过。

早期一次全回归在修改源码仍进行时运行，旧E15隔离恢复测试按冻结hash拒绝 `Source changed`；不是正式服务器实验崩溃。修正工作次序后源码保持稳定，完整420项门禁重新通过；原失败证据保留。另有新增测试夹具未建inputs目录的问题，修正夹具后五组事务测试通过，未改生产算法或降低门禁。

单次1200/2400秒预算在engine clock内包含初始化与相同轻量observer。最终exact复验、导出及调度开销需由两节点同时pilot实测另加；纯预算5小时不应表述为保证5小时完成。24base为独立统计单位，H/T和两个seed为配对观测；480runs不等于480个独立实例。
