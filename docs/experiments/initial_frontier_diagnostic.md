# 初始化前沿诊断协议

## Material Passport

类型：初始化质量与构造来源诊断。用户于2026-10-11授权优先启动，再回收分析D8。
运行基础是D8冻结源码d5374fe；新增诊断不改变初始化、SSGS、exact、MOEA/D或默认配置。
算法质量尚未验证。初始化产生的非支配集合和经验union不称真实Pareto前沿。

## 要回答的问题

1. 当前单次100成员初始化的目标覆盖、非支配比例和构造成本如何？
2. 与同样100成员的随机初始化相比，混合初始化有无质量或覆盖优势？
3. 重复初始化能否填补单次缺失的区域，还是反复产生相近的目标值？
4. 十种构造来源各自偏向哪一端；某些近似均衡配额是否产生大量被支配点？
5. 在D8同一实例上，初始化与已有BASE最终经验前沿的差距是否很大？

## 对照与正确性

每次成功初始化的目标规模都是100，扰动0.1、尝试上限10000，显式RNGManager(seed)的initialization流。
MIXED逐个记录构造来源并与原initial_genotypes核对完整个体及RNG后态。
RANDOM就是原第7号模式（Random OS + Random MS）；另九个单模式控制保持原generate逻辑。
单模式不能补足100时保留实际数量、尝试次数与不足标志，不偷偷转用随机方法。
构造成功后只做SSGS和exact，不做进化、Polish、动作或额外筛选。
每个初始解再次独立exact复验，保存genotype、schedule、evaluation、来源与完整产物SHA。
所有方法使用相同实例与相同种子编号，记录实际构造与评价成本；不同方法并不消耗同一长度随机流或相同CPU时间。

## 场景矩阵

50/100/200 jobs，每种规模六场景，每场景两个独立base，H/T两电价，共36base、72实例版本。
场景分别为原mixed、集中release=0、KV delay乘4、compute乘1.5上限0.95、VRAM乘2上限15.5GB、Demand rate乘5。
所有无关字段保持，末段电价覆盖保守串行上界；完整生成参数与输入JSON保留。
每实例版本11方法，初始化seed从11001开始连续取1至10个。
正式seed数仅在看任何质量结果之前由技术预跑、剩余时间和资源选定，冻结在manifest；禁止按结果扩样。
两节点按case序号分片，同一base的H/T/所有seed/所有方法同host。
各seed轮先覆盖全部实例版本，再增加重复；组内方法循环换位。此顺序只平衡位置，不宣称严格Williams前序均衡。
技术pilot用不同base、seed11901：18base/36实例版本/396初始化；不混正式结果。
单元设计测试用小实例fixture；真实50/100/200输入另行独立验真，不能以fixture替代。

## 测量与图

按每个实际实例分别绘制所有初始点、当次非支配点、方法来源、重复seed经验union。
报告可行率、基因型/目标去重、ND数量、两端覆盖、最大归一化前沿间隙、构造/SSGS/exact/复验时间及RSS。

这种参照只比较观察到的初始化，不代表最优性；完整D8回收后，复用其冻结初始基因型，并与同实例BASE最终archive及全组共同经验前沿作匹配观察。
不得跨实例混画目标点；代表图按事前场景与base编号选择，同时提供全量图，不能只展示效果好者。
重复seed不是独立base；比较先平均同base H/T/seed，场景与规模完整呈现。每cell两个base仅用于定位问题，不作强泛化或因果声明。
构造来源在混合种群中的贡献是观察结果，单方法对照不是在线算子反事实。
