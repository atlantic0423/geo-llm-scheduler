# R1 区域块复用离线诊断

状态：开发诊断。此模块不接入搜索、不修改默认算法，也不以离线结果证明在线性能。

## 输入和研究问题

输入为 terminal-gates 批次的 GS4_GUIDED_RAND_SWITCH_D4 对照臂：冻结120实例、每规模40例、seed 16。源版本为 `3c3da11a601f0cc42fea9a1b0f75ff840d7a548c`。使用回收包中的实例，明确保持该批负载功率模型；与基础面板相比，只有 power_model 字段不同，基础实例逐项核对原 manifest。脚本逐文件检查生产源码，Windows换行规范化后与运行清单SHA一致。

研究问题：在相邻方向的终态种群中，是否存在整解不能改善接收方向、但复用一个区域能改善接收方向的情况？改善能否形成已有前沿之外的点？

这不是在线子代日志。终态供体所在槽位不等于其历史出生槽位，离线频率不能解释为在线触发率。历史全局理想点没有完整保存；统一比较采用原种群、精修前和最终前沿的最小值，再与当前候选取小，尺度最大值来自原种群。

## 可遗传性条件

区域内任务集合必须相同且非空。机器分配由供体对应区域复制；接收者OS中属于该区域的位置依次填入供体的区域子序列，其他位置保留。

条件是：所有任务P/D同区；资源日历按实例独立；两个父代都可由当前确定性SSGS复现；模型无跨区域共享容量或链路约束。对每个区域的局部OS顺序作归纳：第一个操作的释放条件、机器及日历相同；若前缀已相同，下一操作的前序完成和同区KV延迟相同，目标实例日历相同，因此最早可行开始时刻相同。跨区域OS交错不会改变该日历。这个论证只适用于满足上述条件的SSGS输入，不适用于任意有意等待的精修排程。

实现先核验全部父代，再对每个抽样混合基因型完整解码，逐工序核对预期拼接时序；完整exact检查可行性，并由独立事件区间积分核对TOU与每个固定900秒窗口。

## 计费边界

设批次结束时刻为

$$
H(x)=\max_r H_r(x_r).
$$

区域贡献必须在同一个全局时域内评价：

$$
F(x)=\sum_r F_r(x_r),\qquad C(x)=\sum_r C_r(x_r,H(x)).
$$

直接拼接原父代的区域账单通常不成立：供体和受体的原始结束时刻可能不同，新解也可能改变结束时刻。未修改区域的闲置尾段和需量窗必须校正。本次只测完整评价路径，没有实现或声称增量加速。

## 采样和报告

- 使用实际20槽位邻域，遍历有向供体—接收者—区域，排除供体等于接收者、空区域、不同任务集、相同区域表型。
- 每实例在合格三元组中无放回均匀抽取最多96次；显式主种子20261112和实例key通过SHA派生随机种子。重复槽位对应的不同方向保留，结果按实例汇总。
- 每次从原受体出发，不链式接受；对照和种群不被修改。
- 所有候选独立尝试最终档案，无论是否标量改善。相同目标的新表型被档案接受，不一定增加HV。
- 原始回放报告中的精修前指标只与最后快照比较；最终分析将该快照与最终种群取并集，再计算额外HV，以排除快照之后已实现的正常搜索改善。
- 参考点由原有解固定在两目标范围最大值外10%；新点低于原最小值不截断。报告同实例所有抽样候选的并集HV，不累加各次增益。
- Bootstrap单位为实例，仅描述该单seed面板的异质性；不得将交换对作为独立实验样本。

## 复现

从本研究工作树运行，目录参数由调用方指定；OUT必须不存在。

```powershell
python scripts/r1_offline.py --results RESULTS --instances BASE_INSTANCES --out OUT/panel --samples 96 --workers 2
python scripts/analyze_r1_offline.py --panel OUT/panel --results RESULTS --base-manifest BASE_MANIFEST --out OUT/analysis
python -m pytest -q tests/test_r1_offline.py
```

脚本不会重写输入。manifest记录原始输入和每个结果文件的SHA256。完整结果保存在项目outputs下独立批次；所有失败预检和预跑保留，不计入正式诊断样本。

## 实验前已固定的限制

不加入R2，不调交换频率，不选择有利实例，不调整同规模时间预算，不用精修档案作为供体。在线算法的尝试上限、调用频率、预算计入、随机流和邻居接收顺序需要在下一批实现前单独冻结。

## 本轮离线结果

120例全部完成，11,520个抽样交换；8,750个实例内去重种群表型可重解码，所有混合候选开始时刻误差为0，exact和独立TOU/需量积分通过。

|任务数|整解失败而区域成功|涉及实例|最终档案并集HV平均增益|
|---|---:|---:|---:|
|50|129/3840|28/40|0.006820%|
|100|194/3840|37/40|0.020974%|
|200|312/3840|39/40|0.047540%|

共635次局部救回、104/120例出现机会。三规模最终HV中位增益分别为0%、0.000127%、0.000019%，因此本轮只支持存在局部复用机会，不支持在线算法净收益或晋级。1,303次不能直接拼原父代区域账单，其中442次全局结束时刻变化影响未修改区域账单。独立横向HV积分最大增量差小于6e-16。

下一步优先实际搜索中的在线新子代—邻居观测，覆盖早中晚阶段，再冻结受限完整评价对照；增量路径另做等价性和完整成本验证。不能把离线候选加入已有档案的增益当作等时间新算法成绩。
