# 面向算子与右移的 120 个复杂实例

状态：用户于 2026-10-31 授权构造；本批是面向机制的合成压力测试输入，不改变求解器默认算法。50、100、200 任务各 40 个。所有声明的设计格保留，不按 Q、随机、右移或基线的相对胜负筛掉实例。

## 设计与机制对应

每个规模包含十类结构，每类四个独立输入种子：两次三地域、两次五地域。不同规模也使用独立种子，不把同一个大实例的裁剪版本当成独立样本。种子公式和全部参数写在 `mechanism_instances.py` 与生成清单中。算法验收种子为 16901，和输入生成种子分开。

| 类别 | 实例结构 | 对应机制 | 为什么初始化之后仍可能有机会 |
|---|---|---|---|
| F01 | 三波突发、长短任务交错 | A1、A4、A5、P2_FLOW | 单个排序启发式很难同时消除各机器的资源等待 |
| F02 | 算力密集与显存密集任务混合 | A1、A2、A7 | 单维负载均衡不能充分处理二维资源碎片 |
| F03 | 180–450 秒 KV 延迟与拥塞冲突 | A2、A5、P2_FLOW | 同机路径省迁移，分机路径省排队，需要联合比较 |
| F04 | 区域电价相位不同、便宜区域随时间反转 | A3、P2_MIXED、右移 | 静态便宜区域排序不能覆盖实际执行时间变化 |
| F05 | 相对便宜地域只配置两个机器 | A3、P2_MIXED | 低价与拥塞发生冲突，不能简单全部迁入低价区 |
| F06 | 长短区间混合、轻量 Prefill 并发 | A7、右移 | 忙碌区间并集还有压缩和重新覆盖机会 |
| F07 | 较强需量费、不同地域固定窗峰值 | A8、P2_MIXED、右移 | 降 TOU 不一定降总费用，需检查所有峰窗 |
| F08 | 600 秒高低价交替、长 Decode 排队 | 快速右移、A1、A4 | Prefill 后继等待余量可能跨过下一次降价边界 |
| F09 | 更多轻量并发 Prefill、较紧容量 | COMMON 联合右移、A7 | 单独移动可能被其他任务覆盖，联合移动可能改变忙碌并集 |
| F10 | 750 秒价格段、KV、容量稀缺与资源互补叠加 | 全部机制 | 同时存在分配、排序和时序选择，单一启发式难覆盖 |

这些是交叠的重点类型，不是隔离某个因子的消融。每个类别都保留高低价格交替、多波到达和长 Decode，给右移提供基础条件。

F05 和 F10 的地域机器数有下限。在总机器数正好等于各地域下限之和的设计格中，地域容量相同，便宜地域只保留价格差异。F07 提高需量费用权重，并列峰是否出现取决于实际调度。

## 不改变数学模型的输入变化

- 所有机器仍支持 Prefill 和 Decode，均为 16 GB 可调度显存、归一化算力容量 1、idle/active 功率 0.06/0.4 kW。
- 每个作业的阶段 profile 不随机器或地域变化，P/D 仍须位于同一地域。
- 五种任务类型混合：交互短任务、Prefill 算力密集、显存密集、长 Decode、轻量并发 Prefill。任务编号不按释放时间或任务长度排序。
- 基础分时价按高、低、次高、次低四段循环。地域相位不同；600/750/1200 秒等价格段与固定 900 秒需量窗不同步。
- 释放时间有三波集中到达和约 20% 背景到达。机器总数随规模增长，但每地域至少两台。
- 价格时间轴覆盖最保守串行执行上界并留余量；这是输入价格覆盖，不是人为缩短合法调度时域。
- 价格和 profile 是显式声明的合成压力参数，尚未用真实服务轨迹或实际电价合同校准。

## 为什么只设置高低电价还不够

固定 Decode 开始时间时，Prefill 的右移余量为：

$$
\Delta_i^{\max}=S_i^D-p_i^P-\tau_i^{KV}\mathbf{1}(m_i^P\ne m_i^D)-S_i^P.
$$

只有正余量才可能移动。还必须满足目标区间的算力、显存容量，并改变机器忙碌并集或固定窗口功率。最终判据使用完整电费：

$$
\Delta C=\Delta C_{\mathrm{TOU}}+\Delta C_{\mathrm{dem}}<0.
$$

因此本设计同时制造后继排队、轻量并发、价格下降边界和不同强度的需量费。它们只提高机会出现概率，不能从参数直接推出每次调用有效。

## 实际验收协议

1. 全部 120 个输入做 JSON 往返、合法路径、随机 MS/OS 的 SSGS 与 exact 可行性检查；验证规模分层、输入种子和物理内容不重复。
2. 用当前未修改 BILL4 产生 100 个不同 genotype；包括父代和 BILL trial 的 140 次评价全部再用独立 exact 核验。
3. 冻结初始化 Archive，按 Flow 排序等分位抽最多五个前沿解。每个算子与 FAST COMMON 对同一父解分别做 B=3 探针，不串联、不运行 Q 学习、不根据结果修改输入。
4. 右移每个候选验证完整可行、基因不变、全部 Decode 开始时间和 Flow 不变、总电费严格下降，并交叉核对增量电费与 exact。保存每个成功父解的前后调度证据。
5. 统计有正余量、找到降费、调用空率、候选来源、各算子的新增初始前沿覆盖；报告中明确这些是离线前沿抽查比例，不是在线空调用率或整程提升。
6. 对预先固定的十个 100 任务输入（每类一个、奇数类 r01/偶数类 r03），运行原 BILL4＋MOEA/D 五代，再做同样的算子/右移探针。检查初始化指纹相同；仅作早期耗尽诊断，不用于算法胜负或完整预算结论。

HV 使用全部初始化评价的固定 min–max 范围，避免初始前沿只有一两点导致归一化退化。任务自身处理时间之和只作为 Flow 的宽松下界，不能把相对该下界的差额宣称为可实现的改进比例。

## 复现

```powershell
python scripts/build_mechanism_panel.py --output outputs/mechanism_stress120 --audit --workers 4
python scripts/probe_mechanism_baseline.py --output outputs/mechanism_stress120
python scripts/summarize_mechanism_panel.py --output outputs/mechanism_stress120
```

可将 `--historical-inputs <旧批 inputs 目录>` 传给第二条命令，用同一初始化种子和 FAST COMMON 探针重放此前资格与选解批次固定的八个旧输入，各规模四个。旧输入只读，报告按规模列旧批和新批的父解命中率及降费量。P2 的离线算子探针使用统一的初始化评价范围计算修复权重，报告口径对应同父解的一次调用。

已存在的实例会重新生成比对，内容不一致就拒绝覆盖。已完成的验收可续跑；需重做验收时应使用新的输出目录。manifest 保存实例、源码文件校验和与输入设计。

本批不自动启动服务器实验。正式比较预算仍为 50 任务沿用原 600 秒，100 任务 1200 秒，200 任务 2400 秒，包含初始化；所有方法必须采用同一时间口径。此处五代探针另列，不能混入这些正式预算结果。
