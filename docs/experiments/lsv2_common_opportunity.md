# COMMON：资源预筛与选解实现（开发筛选候选）

本轮补完此前五点诊断中的资源预筛、诊断开销和选解规则；对更大邻域做同输入离线审查。所有新增行为均显式启用，不改变默认算法。实现完成不等于整程效果成立，尚未启动本轮服务器实验。

## 1. 与原五点的对应

| 原问题 | 本轮处理 | 研究边界 |
| --- | --- | --- |
| 重复输入、重复基表、无筛选作用的排序、全池方向诊断 | 继承已验收 COMMON 复用；新增加空输入资格排除和按需方向标签 | 成功输入仍可重试；关闭标签须在日志中显式标记未采集 |

| 怎么选解 | 已证实空输入排除、少处理优先、区域内前沿优先、子问题代表 | 不硬删全部零即时 HV 或被支配输入，不增加冷却时间和学习状态阈值 |

## 2. 资源预筛的准确含义

同机器活动组的每个成员沿时间轴共同右移。冻结组外任务，分别建立组内和组外资源分段。组内活动段为 $[a,b)$，组外活动段为 $[c,d)$；两段在共同位移 $\delta$ 下相交的条件是：

$$
c-b < \delta < d-a
$$

如果相交时算力或显存总量超过原 Coding Contract 容差，区间内部可以证明不可行。将这些开区间裁到原合法位移范围并合并；原候选位移落在已证明的内部时直接拒绝。其他位置仍执行原 `_fits`。这减少逐成员重建和扫描，不会因为估计收益低而删候选。

浮点实现使用非负资源和的保守下界；区间按机器表示误差内缩。表示误差保护不是新增物理约束容差或可调研究参数。半开接触点、极短区间和接近容量容差的情况回退参考。没有将 `rejects=False` 解释为已证明可行。

`ShiftCalendar` 按输入与组建立；完整搜索结果仍使用上一版有界物理输入缓存。新模块统计 `calendar_builds/pairs/rejected/reference_resource_checks`。位置拒绝率、资源检查次数和实际耗时分别报告，不能把拒绝比例当加速比例。

固定输入 benchmark 已发现：虽然大量位置可提前拒绝，建表可能抵消收益。因此这是独立实验开关，不因正确性通过就自动替换原资源检查。选解策略也支持 `common_fast/common_peak`，不要求使用日历。

## 3. 空输入资格与访问记录

资格来自完整生成器搜索的严格证据：当前设置下单任务路径的首轮没有可执行改进，且确定性的组候选池为空。不是依据 Archive 拒绝、即时 HV 为零、Q 负奖励或 deadline 判断失败。

匹配范围包括实例对象、完整 MS、所有原始 starts、候选预算、部分/全部任务范围、峰值扩展、日历开关和算子配置。新调度、新范围、新邻域重新搜索。OS 不影响这里的物理可行性与账单；复用的输出始终挂当前 genotype。空证书只表示当前配置邻域为空，不表示所有可能邻域都无机会。

缓存和访问次数仅保留当前种群加轨迹终点的物理去重池，避免无界增长或任意缓存容量。证书排除发生在抽样前；如果全部输入都有证书，记录 `no_opportunity`，不执行生成器、不调用 exact、不消耗选解 RNG。筛选成本仍计入共享 LS 时间。

访问次数仅在完整生成并完成所有候选 exact 处理后增加；空搜索完成也增加。中断、deadline 和部分评价不增加。新进入池的物理输入从零计数；动态池持续产生新输入时不承诺旧输入有固定等待上界。

## 4. 五种选解规则

共同输入池固定为当前种群加轨迹终点、按物理调度去重。先剔除完全匹配的空证书，之后：

| 策略 | 跨区域分配 | 区域或方向内部选择 |
| --- | --- | --- |
| `eligible_random` | 按剩余输入数自然分配 | 均匀随机 |
| `eligible_region` | 在非空三区域中选累计完整调用秒数最少者 | 均匀随机 |
| `fresh_region` | 同上 | 完成搜索次数最少的一层中随机 |
| `frontier_region` | 同上 | 先取最少访问层，再优先该层内非支配输入，随机打破并列 |
| `fresh_direction` | 原 MOEA/D 有输入的细方向轮转 | 最少访问层中选该方向 Tchebycheff 最优代表，规范标识打破并列 |

区域成本包括选解、诊断、构造、exact 和回流；另保留旧服务时间字段作兼容诊断，但不重复收取全局 LS 时间。这里改为完整成本，是因为上一批便宜空调用的选解与记账开销并不为零。全池无资格时无被选区域，其成本仍进入全局 LS。

`frontier_region` 的前沿仅针对该区域最少访问层，采用逐目标不变差且至少一目标改善超过数值容差的无环偏序。不是整个 Archive，也不永久排除被支配输入。这样避免反复精修一个老前沿点而永远不处理同池其他输入。

`fresh_direction` 使用既有方向关联和标量化，不称为 MOEA/D-DRA；没有估计效用、设滑动窗口或新增收益权重。随机选解和区域策略可不计算全池细方向诊断；方向策略仍必须计算。

PLS 文献中的未访问解管理支持研究“已搜索输入与未搜索输入应区别对待”，但不直接证明本项目的选解有效。这里仅复用管理思路，并保留成功输入的重试机会及被支配输入的资格。[Drugan & Thierens, 2012](https://link.springer.com/article/10.1007/s10732-012-9205-7)。MOEA/D 的分解与资源分配提供另一参照；本轮方向轮转没有实现其自适应效用分配。[Zhang, CVPR 2023 tutorial](https://multiobjective-ml.org/2023-cvpr/chapter2/)。

## 5. 八配置入口

| 配置 | 行为 | 主要比较 |
| --- | --- | --- |
| R0_NONE | 旧 C0，无外置右移 | 模块总体价值 |
| R1_FAST | 旧 C2，等价复用 COMMON＋同池随机 | 原参考 |
| R2_CALENDAR | R1＋资源预筛＋不计算无用的全池方向标签 | 工程组合；两部分另有固定输入独立计时 |
| R3_ELIGIBLE | R2＋已证实空输入排除，仍均匀随机 | 抽样前资格过滤的价值 |
| R4_REGION | R3＋三区域完整成本平衡 | 区域分配 |
| R5_FRESH | R4＋区域内最少访问层 | 新机会覆盖 |
| R6_FRONTIER | R5＋层内前沿优先 | 前沿偏好 |
| R7_DIRECTION | R3＋细方向轮转、最少访问层及标量代表 | 子问题路线，视为组合方案，不作单因素归因 |

统一 Q1/NET/G9/B3L3、内部不含 P3、共享 20% LS；每次运行 Q 从零在线学习。轨迹最后一步 terminal 更新以后才调用右移，外置收益不写入 Q 奖励。Decode、MS 与 Flow 冻结；所有完整候选统一 exact、Archive、回流并刷新诊断。

原 seed16901、100任务 d06/d09/d12/d13、200任务 d01/d07/d09/d14。每次总预算分别1200/2400秒，包含初始化。8配置×8实例为64run。实现入口 `experiments/lsv2_common_opportunity.py`，runner `run_lsv2_fast_rightshift_campaign.py --study opportunity`；启动前仍须按服务器协议冻结源码、输入、配置、初始化及 exact 预检。

R0/R1 与旧配置逐值一致；R1/R2 在固定输入、固定随机流且无计时中断时等价。墙钟预算下更快或更慢会改变后续搜索轨迹，不能要求整程输出逐值一致。

主判据为同预算最终 HV/IGD+ 与逐实例胜负。机制量分别报告实际生成器调用、证书排除数、全池无资格次数、实际空生成数、首次/重复输入、实际成本、exact、Q 步数和前沿回流。降低实际空率不能单独证明算法变好。

## 6. 第三点和其他方向的取舍

需量上包络切换位置保留为已实现的可选扩展，上一批确有真实补漏；不与本轮选解同时叠加来宣称选解贡献。不等位移继续用已有 COORD 同输入审查其边际收益和成本，暂不盲目加深。每个输入上的较小降费并不自动等于整体前沿的改善。

可移动子集值得下一轮诊断，尤其是整活跃组被 Decode 或零 slack 成员挡住的情况。但“某活动段被挡住”不等于一定漏解：同组可能从别的活动段生成，单移动也可能覆盖收益，必须对同输入做候选去重和 exact。尚未实现任意子集枚举。

跨组链式搜索、跨机器需量联动和移动 Decode 的语义/开销变化更大，暂缓。优先把“构造出降费解后为什么没有进入前沿”和“回流后是否产生后代价值”统计清楚；不基于即时零 HV 删除动作。自适应按收益分配区域属于进一步研究，需要收益和探索口径，当前不另加一层学习器。
