# 资格过滤与选解：整体方案

## 1. 这次回答什么问题

用户已选择优先检验“资格过滤与选解”，并要求本轮只在本地实现。沿用已有 FAST COMMON 右移，不增加更大邻域、资源日历、需量折点或新的 Q 状态奖励。将上一轮已实现的选解组件整理成专门实验，避免把资源预筛的建表成本混入选解结论。

研究问题依次是：

1. 在同一调度已经完整搜空之后，将它排除出抽样池，能否把时间用于更有价值的输入？
2. 剩余机会按三个区域分配，是否优于整个池均匀随机？
3. 同区域中优先少处理的输入，是否优于反复抽老输入？
4. 在少处理层中优先非支配输入，是否提高前沿收益？
5. MOEA/D细方向代表路线是否值得保留？这条路线中少处理优先有没有帮助？

现有证据只支持提出这些问题：旧调用日志存在同物理输入完整搜空后的重复调用；上一轮区域服务时间平衡存在便宜空输入反复被选；资源日历虽拒绝大量位置但没稳定提速。不能预设本轮一定胜过无右移或随机参考。

## 2. 固定的算法与公平比较口径

- BILL4初始化、MOEA/D进化、Q1/NET/γ=0.9/B3L3、A8原门与当前动作池保持；Q内无P3，A3/A4/P2_MIXED等不另删。
- 每次run从零在线学习，共享Q表仅在该run内延续；没有额外预训练。
- 原20%累计LS时间门，Q轨迹与外置右移共同计费；轨迹terminal更新在右移之前，右移收益不写回Q。
- 右移统一FAST COMMON：原部分Prefill单移＋自然并行组相同位移；冻结MS、Decode和Flow；最多3个完整输出，经exact、Archive及原回流规则处理。
- 资源日历、需量折点和COORD全部不进入本矩阵；已有实现保留在旧研究模块，不删除。
- 随机/三区域配置统一省去算法不需要的全池细方向诊断。方向配置保留算法必需的方向关联，其额外成本照常计费。不是假设各策略CPU成本相同。
- 100任务每run1200秒，200任务2400秒，均包含初始化。seed16901；100任务d06/d09/d12/d13，200任务d01/d07/d09/d14。使用旧输入与原校准，不重新拟合。

## 4. 什么输入有资格

输入池是当前种群加本条Q轨迹终点，按完整MS及原始starts物理去重。不是只从电费端选择，也不是只从Archive中选择。

仅当同实例、同MS/starts、同算子配置、候选预算、部分/全部Prefill范围及邻域设置下，单任务分支完整首轮无可执行改进、确定性组分支也没有候选，才有空证书。该调度在本次池中被排除。

以下情况不能当作无资格：零即时HV、被Archive拒绝、Q负奖励、曾经成功但这次可能无新HV、deadline跳过或部分评价。成功候选仍走当前Archive/exact流程。物理调度或搜索配置变化时证书失效；只保留当前候选池仍存在的记录，不引入冷却时间和缓存容量参数。

资格过滤只减少重复搜空，不预知新输入是否为空。全部输入都已有证书时记录 `no_opportunity`，不调用生成器或exact、不随机抽空池；筛选成本仍计入LS。它表示当前配置邻域无未处理机会，不表示所有可能右移都无收益。

## 5. 区域和内部选择的定义

三区域沿用冻结归一化Flow的流时间端、中段、电费端，不新增分段阈值。选择仍有资格候选的区域中累计完整右移成本最小者；并列按原区域游标轮转。

$$
r^*=\arg\min_{r:\,|E_r|>0} T_r
$$

$E_r$是区域内合格物理输入，$T_r$包括选解、构造、exact及回流等完整调用耗时。相比旧服务时间口径，这是有意改变的研究策略。全池为空时没有被选区域，只记全局成本。区域标签随归一化框可能变化，累计计时保留；这是现有分类机制的延续，日志解释需注意。

“少处理”是在所选区域/方向内，取完整处理次数最少的一层，新输入从0开始。不用固定年龄阈值，处理中断不增加完成次数。动态池持续出现新输入时不承诺每个老输入都有固定再访上界。

“前沿优先”仅针对该区域最少访问层。要求所有归一化目标不变差，且至少一目标改善超过原数值容差，避免容差偏序循环；并列随机。被支配输入仍保留，前沿输入完成处理后它们可能进入下一次最少访问层。

“方向代表”使用原MOEA/D方向关联与归一化Tchebycheff标量，跳过没有合格输入的方向。S6直接取代表，S7先取少处理层再选代表；标量并列按规范身份确定。两者均不是DRA，没有效用滑动窗口或新学习器。

## 6. 日志与分析：防止空率分母误导

保留原逐次物理输入、调用状态、exact、费用/HV增益、Archive/回流、成本及资格排除日志。增加本地汇总接口，按单个run计算：

| 指标 | 分母或含义 |
| --- | --- |
| 完整空生成率 | `empty / (empty + evaluated)`；排除未完成和全池无资格 |
| 未生成比例 | 无资格/截止等未启动生成的次数占模块尝试数，按状态分列 |
| 资格排除暴露数 | 每次池筛选排除数的累加；同一输入可重复计，不能叫独立解数或节省调用数 |
| 实际生成、完整/部分评价 | 分别计数，不用跳过来伪造低空率 |
| 首次/重复选中输入 | 使用原始MS/starts键；包括无变化输入的重复选择，OS不区分 |
| 同输入已完整空调用后的再选择 | 仅为本run同范围下已观测重复描述，不推断没执行策略的反事实 |
| 完整耗时及三区域成本 | 汇总原秒数字段；不把service与full再次相加 |
| 降Bill／即时HV／回流 | 分开统计；零HV不能一概判无效 |

线上比较主指标仍为每个实例同预算最终HV；IGD+、前沿覆盖、Q动作数/子代数、实际LS份额、单位秒HV成功数辅助解释。逐调用HV增量基于会变化的框，不将其简单相加当最终HV。

统一每个实例的参考前沿/归一化框和HV参考点，所有8臂使用相同口径；IGD+参考集取本批8臂最终前沿并集，明确仅是已知参考集。与历史批次的指标值比较需重新使用同一框。

8实例×1seed是开发筛选，不能把调用数当独立样本。报告每实例差值、胜/平/负与均值/中位数；7项HV主对比采用实例层面的双侧配对符号翻转检验和Holm校正。小面板效力有限；未显著不等于等效，不据单seed改默认。若有失败/缺失，先报告完整性，不悄悄删掉困难实例。

若过滤只降低空率但最终质量没改善，不认定获胜；若更高HV以更少Q步实现，属于整套方法收益；若方向偏好只对少数实例有帮助，保留条件性观察，不能事后冻结一条普遍规则。

## 7. 本地实现与验收顺序

1. 复用上一轮空证书、FAST COMMON和五种选解组件；新增S6资格方向参照，不改旧策略行为。
2. 新增独立 `lsv2_eligibility_selection` 实验模块及 `eligibility` runner入口；旧opportunity矩阵保留原样。
3. 增加run级日志汇总函数与读取压缩日志的本地CLI，显式区分跳过、真空、部分评价和零即时收益。
4. 测试配置单因素关系、方向代表/少处理差异、真实证书失效、全池无资格、deadline、terminal Q信用及exact不变量；差分验证旧随机参考和无资格排除时的资格随机。
5. 在已有100/200实例物理输入上做固定调用次数的本地重放，验收每种选择器完整流程；成本平衡使用真实计时，不能承诺每次重放的选择序列完全相同。这是技术验证，不拿来做在线质量结论。
6. 显式绑定当前源码运行完整本地质量门；不复用上一轮CI当本轮验收。保存测试日志、源码版本、输入SHA与本地方案清单。

本轮不部署服务器、不运行64个正式墙钟run、不推送GitHub。8×8矩阵总求解预算为32小时（串行预算和，非预计完成时间）；以后开跑再按实际服务器资源估算。
