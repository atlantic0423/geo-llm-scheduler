# LSV2 研究臂：四臂开发批次协议（2026-10-26）

## 背景

第一、二层诊断（`outputs/ls_redesign_research_20261026/REPORT.md` 第 6–7 节）发现：LS 的奖励与接受不对齐、起点集中在缺口最小的 Flow 端、A6 无效、缺少目标导向的破坏重构和不伤 Flow 的电费移动。本批把三个原型与新的调度、奖励、接受规则组合成默认关闭的研究臂 LSV2，与两个参考臂比较。

## 臂

- `BILL_RANDOM`：原 `BILL_PERMUTED` 普通 MOEA/D（BILL4/P100，permuted 邻居替换，无 LS/Polish）。
- `MAIN_RANDOM`：原 `STRICT_TWO_FOCUS` 主参考（Q42、B6/L5、严格细方向门、零质量容差、两重点 Polish、A3 tariff）。
- `LSV2`：BILL 引擎不变（同一 BILL4 初始化、变异、替换），用引擎的可选 `interleave` 接口插入时间份额 LS；没有触发门，也没有 Polish。
- `LSV2_NOGAP`：同 LSV2，只把起点规则换成“Flow 端为主”（80/15/5），用来区分选起点本身的贡献。

## LSV2 规则（`src/geo_llm_scheduler/lsv2/search.py`）

1. **时间份额**：在每个子代位置之前检查；LS 累计墙钟低于“初始化之后的搜索时间”的 20% 时，执行一条 LS 轨迹。份额写在 `LSV2Config.time_share`。
2. **冻结框架**：轨迹开始时若距上次刷新已满 50 个 LS 步，就用当前 Archive 前沿的 ideal/nadir 重新冻结；HV 参考点 1.1。
3. **起点**：从 Archive 前沿按缺口分数抽样（`SeedSampler` 的 gap 规则，端点加成 1.0，轨迹无 HV 增量时该点折扣 0.5）；NOGAP 臂用 80/15/5 规则。
4. **段与控制器**：每步按当前解在冻结框架中的归一化 Flow 三等分确定段（Flow 端、中段、电费端）。无状态滑动窗口 UCB 老虎机，臂 = 段 × 算子；窗口为最近 100 次拉动；当前段内窗口中没拉过的臂先选；否则得分 = 窗口均值 ÷ 当前段候选臂的最大均值 + 0.5·√(2 ln N / n)。
5. **算子**：A1、A2、A3、A4、A5、A7、A8、原型 2 FLOW 与 MIXED、原型 3；去掉 A6。算子参数沿用 MAIN 配置（A3 tariff）。A8 按段门控：该段最近 8 次 A8 调用中至少 4 次、且空调用（无提案）比例不低于 75% 时关闭，关闭期间每 20 个该段 LS 步重新放出一次。
6. **评价**：每步 B=6；全部提案走正常评价网关（结构候选走 SSGS，全部 exact），所有完整可行候选尝试进 Archive。
7. **奖励**：该步 Archive 在冻结框架内的 HV 增量 ÷ 该步实际耗时；被局部拒绝但进了 Archive 的候选也计入。
8. **链式接受**：优先支配当前解的候选（多个时取“起点附近缺口”缩小最多者）；否则取本步新进 Archive、使起点附近缺口缩小最多的点；都没有则留在原解。“起点附近缺口”= 轨迹开始时起点在前沿上左右邻点围成的矩形内的已达面积。被接受的时间类解（A7、A8、原型 3）刷新资源等待诊断。轨迹长度 5 步。
9. **回流**：本步新进且留在 Archive 的点，在当前种群框架下关联方向，尝试替换该方向邻域内最多 2 个个体，每个邻居按自己的权重比较。
10. 随机性：`lsv2:seed`、`lsv2:bandit`、`lsv2:op:<算子>` 三类命名流；参考臂的随机流不受影响。

原型 2 已提速（`_slots` 单遍扫描、只重算被改动实例的负载、每次放置内缓存延长终点的账本），固定 RNG 下提案与 ca4e1dc 逐个一致（`tests/test_lsv2.py`）。

## 实例、随机数和预算

component33 原 32 输入（16 开发父 × 2 变体，20/50/100/200 任务），原字节与 SHA 不变；单一新 seed 16601；32 块 × 4 臂 = 128 run。生产预算 300/600/1200/2400 秒，含初始化。16 父是重复使用的开发面板，不是留出。

## 分析（预先约定）

- **参考前沿**：每个输入取四臂最终 Archive 的共同经验非支配并集；以并集的 ideal/nadir 归一化，参考点 (1.1, 1.1)，计算每个 run 的 HV 与 IGD+。
- **主比较**：`LSV2−MAIN_RANDOM`、`LSV2−BILL_RANDOM`，各看 HV 与 IGD+，共 4 项，Holm 校正。
- **统计单位**：先按父实例平均两个变体，16 父为独立单位，按规模分层；20k 次分层 bootstrap 区间，100k 次配对符号翻转检验。
- **次要（描述性）**：`LSV2−LSV2_NOGAP`；对已知最好前沿（构建方法同 `ops/analyze_headroom_20261026.py`）的差距；按 Flow 端、中段、电费端分段的 IGD+；实际代数与 exact 次数；老虎机最终的“段 × 算子”选择分布与算子选择空间；同时报告等墙钟和等 exact 次数两种口径（`archive_events.json.gz` 记录每次 Archive 插入的 exact 序号与时间）。
- 经验并集不能称为真实 Pareto 前沿；未显著不等于等价。

## 运行与验收

### 2026-10-27 数值并列修正（后续研究版本）

历史批次仍以其冻结源码解释。后续 LSV2 在候选资格判定后，先取局部 HV 增益的全局最大值，再把与该值满足 `close(..., TOL.scalar)` 的候选视为并列；支配分支在并列集合内再按归一化目标和的全局最小值作同样筛选；最后用固定 phenotype identity 决定。每级均锚定极值，不使用不具传递性的两两近似比较排序。相对与无量纲绝对容差均沿用 Coding Contract 的 `1e-9`。

此修正解决 n200 开发快照中电费末位差导致不同 Python 版本选中不同下一步解的问题。exact 目标、支配判断、gap 分支的严格正收益资格、候选预算与 RNG 不变；容差内候选的选择可能有意不同于历史源码，因此旧结果不回写，也不承诺任意平台的整程逐解一致。回归在 `tests/test_lsv2_numeric_ties.py`，真实快照复核入口为 `scripts/check_lsv2_numeric_replay.py`。

219 服务器独立根目录，最长预算优先派发，单 CPU 绑定，每 worker 3 GiB 地址空间上限，保留至少 200 GB 可用内存与磁盘。每个 run 结束后独立 exact 复核最终种群与 Archive，按 SHA 写完成标记。LSV2 是新代码路径，正式前先跑 16 次短预算 pilot（45/60/120/240 秒），不计入正式样本。
