## 四组及共同边界

`JEV_E05`、`JEV_E09`、`MAIN_Q`、`BILL_MOEAD`。两个 Jev 组每个 LS 步重新询问当前解的动作分布，按实际抽中对象逐层选择工件及操作，完成后询问停止，最多五步。两档各选择层的贪心概率分别为 0.5 和 0.9，其余概率按完整 Jev 分布抽样。当前失败/等待/请求/token 守卫仍适用，触发时不得复用旧分布。

共同原始 component33 32 输入，16 开发父问题及各自两个变体，20/50/100/200 工件。按原输入字节及 SHA 复制，不重新生成实例。所有组使用相同 BILL4/P100 初始化；初始化、特征、排队、HTTP、候选构造及搜索均计入生产墙钟。生产预算依规模为 300/600/1200/2400 秒。每个进入的 Jev LS 仍为 strict/delta0、同一 incumbent、B6/L5、两重点 Polish、原邻域替换和 exact/Archive 规则。MAIN_Q 和 BILL 对照直接调用已验收的原控制路径。

新增运行入口 `scripts/run_jev_comparison.py`；四种 Williams 顺序平衡组别位置及相邻前驱。建议新种子 17401、27401，尚非派发事实。每一完整块的四组必须同 host；重复开发面板不作为新留出。

## 费用范围与守卫

每个 Jev run 保留原上限 4000000 输入 token、512 POST、15 秒单问、等待最多生产时间一半。四组入口在写新实验目录前，为所有 Jev run 预分配完整 token 上限，另留 0.1 美元技术校准。只有总上界不超过显式美元上限才允许准备；不借其他 run 未使用额度扩大某个 run，不存在并发超配同一额度。

全量 32 输入、两 seed、四组为 256 run，其中 128 Jev run。费用上界为 21.504 美元，另加 0.1 校准预留，总预分配 21.604 美元。当前 4.5 美元默认上限会拒绝这一矩阵，不会悄悄削减面板。

可供用户选择的小规模版本：按每规模最小 base_seed 事前选一个父问题，保留其两个原变体，一 seed；8 输入块、32 run、16 Jev run，完整预分配上界含校准为 2.788 美元。只有四个独立父问题，适合技术/描述性试跑，不作为有充分样本的确证比较。此版本同样尚未获规模选择、未准备或派发。

达到单 run token/等待等守卫后，既有实现会进入回退。需报告动作、对象和停止实际调用/有效率、回退及守卫命中；“至少一次有效动作”只是最低处理真实性检查，不代表全程由 Jev 控制。大量回退的 run 只能作为受限处理解释，不能称完整执行了全程模型控制。

## 派发、产物和时间

Linux 派发复用原经过验收的派发器：每个 worker 单 CPU affinity、2 GiB 地址空间，nice10 和项目专用 cgroup；每次接纳重读资源，采用 220 GiB MemAvailable 加所有活动进程最坏增长及 HTTP 子进程余量的守卫，目标保留至少 200 GiB。最多 96 求解 worker，HTTP 共享队列暂设四个槽；队列等待也扣生产时间。实际并发、cgroup、剩余内存和限流须服务器预跑后冻结，当前未测。

保存初始/最终 P100、Archive、Q42、anytime、诊断、完整脱敏请求/响应、逐步动作/停止记录、英文模板、配置及各产物 SHA。Jev 初始化现在发出与对照一致的 `initial_ready` 观察事件，使初始种群可保存并和预检指纹比对。所有最终 P100 和 Archive 成员都重新调用独立 exact，只有全部可行且与保存评价一致才可验收。全回退 Jev 不可验收；失败保留产物并停止新派发，不自动重试。

全量总生产预算 288000 秒，即 80 solver-hour。96 并发下理想除法下限约 50 分钟，考虑 40 分钟最大单 run、尾部及审计，约 1–2 小时是资源恢复后的初步计划，尚非实测 ETA。小规模总预算 36000 秒，即 10 solver-hour；足够并发时至少需 40 分钟长 run 加审计。未连接服务器和冻结并发前，不承诺具体完成时刻。

## 验收边界

专项覆盖长上下文头及预约、原输入防篡改、完整父块/变体选择、预分配预算拒绝、Williams 顺序、队列超时不发送、四组产物写出/最终 fresh exact、全回退拒绝与失败留证。工程通过不替代 Jev 费用/并发预跑，也不等于服务器已经启动。

再用每规模一个原初始解、显式注入选择离线构造B6，对A1–A8记录实际产生的对象问题数，按原MAIN_Q动作曝光加权，保持旧工作量约每run 10.03/15.00/17.15/16.35美元；四规模各一输入、两epsilon合计约117.07美元。该数只说明调用量，不是会实际扣费的预测。抽样对象/可行机会改变会改变问题数，完整原LS状态未保存，不能声称逐轨迹精确回放。示例200工件A6有20次destroy选择、六候选可达120次对象POST；A8无完整候选仍可能消耗构造问答。

网络每问约1.2–1.4秒时，保留旧工作量仅等网络就需每run数小时，远超300–2400秒生产wall。当前守卫512POST/400万token/最多50%等待会更早生效，实际Jev决策步将大幅少于旧步数，或随后回退。因此此前32run/2.688美元封顶只保证受限处理的费用，不保证完整维持旧LS规模及全程模型控制。

若按实测动作token、单问约1.2/1.4/1.4/1.4秒及50%等待上限粗估，四规模各1父×两变体×一seed×四算法共32run，推算约1.80美元，单run token上限共同封顶2.688美元（校准另留0.1）。两父/规模共64run推算3.61美元，但上界5.376美元超余额余量，不能保证约5美元足够。它们只是等待受限情景；未实测完整run、并发尾延迟或所有对象状态，不能说全程Jev已经可负担。
