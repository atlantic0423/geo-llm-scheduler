## 结论

**证书门控在当前开发回放中真实节省了 A8 构造 CPU，同时保持输出不变。** GUARD_SINGLE 相对新流 REFERENCE 的 base 等权平均 CPU 节省 **14.738%**，描述性 95% CI [13.435%,16.031%]，32/32 base 为正；每调用净省约 **1.858 ms**。GUARD_ALL 为 14.635%，每调用净省 1.847 ms。可继续作为工程优化候选；不能把它称为整个 MOEA/D 的 14.7% 提速或在线 HV 改进，更不能据此宣称论文创新已成立。

## 实测成本与输出

下表成本为平均构造 CPU 毫秒/调用；百分比是每 base 百分比节省再等权平均，不是所有计时重复混作独立样本。CPU/墙钟均实际计时，包含缓存/证书的真实开销。

| 臂 | CPU ms/调用 | 对 REFERENCE 节省 | base bootstrap 95% CI | 有 proposal 调用率 | 平均 best scalar gain |
|---|---:|---:|---|---:|---:|
| GUARD_ALL | 9.93754 | 14.635% | [13.317%, 15.951%] | 43.0869% | 0.00229051279 |
| GUARD_SINGLE | 9.92682 | 14.738% | [13.435%, 16.031%] | 43.0869% | 0.00229051279 |
| LEGACY | 11.72515 | 0.647% | [0.244%, 1.016%] | 42.8048% | 0.00231274356 |
| REFERENCE | 11.78465 | 0.000% | [0.000%, 0.000%] | 43.0869% | 0.00229051279 |

两 guard 的 proposal/genotype/timing/exact 评价、attempts 和父 RNG 与 REFERENCE 一致；观察到的质量增益差为精确零，性能变化来自跳过必然无效修复。GUARD_SINGLE 墙钟净省 1.858 ms/调用，和 CPU 接近，但共享物理 CPU/D3 重叠负载限制仍存在，不当作空闲/冷启动基准。

50 jobs 单成员 CPU 节省 11.796%，100 jobs 17.680%，两规模各 16/16 base 为正。单成员相对全成员平均仅多省 0.01072 ms，探索性 CI [0.00690,0.01389] ms；差别很小，以实现简洁与更窄适用范围为候选选择理由，不放大成重要算法差距。

LEGACY 与 REFERENCE 的随机流本身发生改变：LEGACY−REFERENCE 标签均值 +2.22308e-05，CI [-5.08151e-05,9.55897e-05]。这不支持新流必然更好，也不构成等效性证明。将来在线消融必须保留原 LEGACY 和同新流 REFERENCE，不能把“改随机流+证书”整体提升全部归因证书。
