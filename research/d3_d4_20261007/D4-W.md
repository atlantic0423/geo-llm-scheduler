## 结论

**同采样额度下，PEAK_RANK 明显增加了可用候选和离线 caller scalar 收益，但构造成本也上升。** 有 proposal 的调用率从 43.071% 升至 57.155%，+14.084 个百分点；有正 scalar gain 的调用率从 12.012% 升至 14.999%，+2.988 个百分点。平均 best gain +0.000684619，描述性 95% CI [0.000603935,0.000769833]，32/32 base 为正；相对原均值增加 29.508%。

相对 REFERENCE，构造 CPU 每调用增加 5.187 ms；按 base 等权平均增幅 **47.369%**，CI [43.702%,51.025%]。若只看等 CPU 的离线构造效率代理，收益/CPU 反而约低 9.97%。因此它适合继续作为**候选构造改进方向**，需要先降成本并进行新 base 等时间在线验证；目前不足以采用为默认 MOEA/D，更不是在线 HV 改进或已确认创新。

## 成本归一化的警示

探索代理使用等权 base 均值之比：

$$
E=\frac{\frac{1}{32}\sum_b \bar g_b}{\frac{1}{32}\sum_b \bar c_b}.
$$

REFERENCE 的 E=0.196142598，PEAK_RANK 为 0.176589746，相对差 -9.969%，配对 base bootstrap 95% CI [-12.531%,-7.107%]。这是事后探索指标，未作为冻结晋级门槛；不包含优化器其他部分、完整 exact/Archive/日志、阶段状态变化。它不能替代在线等时间 HV，但足以提醒我们不能只按 29.5% 单次 gain 提升宣称算法更好。
