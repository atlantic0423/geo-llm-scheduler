## 1. 与之前初始化加速的关系

此前 FAST4 已优化 BILL 构造内部的资源日历、重复 Prefill 查询与电价区间积分，正式初始化对照的生产时间几何比为 0.299232，约减少 70.08%，种群、trial 评分、Archive 和 RNG 一致。综合13组的 I4 已使用这条加速路径，因此不能把此前 70% 再算成本次新收益。四选一改二选一或单次会改变候选与随机流，不属于本次语义保持优化。

这次继续查解码、迁移候选构造、Archive 和状态计算。所有结构候选仍完整 SSGS，所有完整候选仍调用同一个 exact evaluator 并尝试 Archive；没有减少 MacroSearch/Polish 候选、缩短轨迹、放松可行性或改变初始化重复恢复规则。

## 2. 已实现的四类工程改动

| 部位 | 原重复工作 | 当前处理 | 保持条件 |
|---|---|---|---|
| A2/A3 迁移负载 | 每个机器路径重扫全部工序与地区 | 调用内复用同一工件/机器占用模式、同一目标地区的分数 | 重新按原工序编号累加，不采用总量减加；候选排名、去重与抽样不变 |
| SSGS 与 earliest | 每放置一个工序、每试一个完成事件都重建机器区间 | 当前 decode 建立临时机器日历；同一 earliest 调用复用固定 others | 半开区间、事件集合、operation 顺序求和及所有 diagnostics 不变；不跨解复用 |
| External Archive | 每次插入/排序反复量化全部存活成员的 starts | 缓存存活不可变成员的原 identity；移除成员即释放 | 不裁剪、不改变容差 dominance；公开成员列表外部替换/清空仍兼容；原顺序和计数不变 |
| RL 状态诊断 | 局部搜索没有接受新解时重新扫描同一个解的 severity | 仅当 current 仍是同一不可变对象时复用原 tuple | severity 不依赖更新后的 ideal/Archive；accepted timing 的 diagnostics 刷新和 next-state/Q 更新仍执行 |

`evaluation/exact.py`、数值容差、接受/替换规则和所有参数未改。新资源日历由 MS/timing 派生，不能成为另一份 assignment 权威。原初始化资源日历保留兼容导入位置，统一调用同一实现。

## 3. 前后计时

下表是最终独立计时，单位为秒，取三次中位数。全部39对确定性摘要见 [benchmark.json](data/benchmark.json)。计时不使用 profiler，以相同固定工作量和 seed 对比原实现；每项三次，交替执行先后次序。完整算法的工程计时包含 P100 初始化、一代搜索与相同的候选/RNG采集，不含正式运行器末尾独立审计及文件导出；分别观察原初始化与 BILL4。它不是300/600秒正式预算实验；单模块覆盖20/50/100/200任务。

| 固定工作量 | 原实现 wall | 优化后 wall | wall 减少 | CPU 减少 |
|---|---:|---:|---:|---:|
| 20任务，原初始化＋一代 | 4.1774 | 2.9366 | 29.70% | 27.94% |
| 20任务，BILL4＋一代 | 5.6792 | 4.0927 | 27.94% | 27.75% |
| 50任务，原初始化＋一代 | 19.2397 | 11.4816 | 40.32% | 40.98% |
| 50任务，BILL4＋一代 | 24.4111 | 19.7440 | 19.12% | 19.17% |

本机这四个固定工作量样本耗时减少约19%–40%，不是正式长预算或总体实例的加速保证。BILL构造仍占时间，因此其总降幅比只看搜索热点小。两种初始化的候选数、接受/入档过程、Q表和最终RNG摘要均严格相同。

| 单模块工作量 | 原实现 wall | 优化后 wall | wall 减少 |

Archive一行是人工互不支配点的独立维护载荷，不是可行调度质量实验，其比例不能代替整程比例。CPU中位数不足0.05秒的微型项不报告CPU比例，避免分辨率产生虚假的100%减少。

## 4. 一致性证据

保留六份原始 Git blob，包含 SSGS、资源函数、Archive、结构算子、初始化日历与 RL trajectory，逐 SHA256 锁定，避免 reference 随新实现一起变化。测试内只临时替换内存函数绑定，不改原源。

本轮新增29项差分检查；首轮完整套648项通过、1项平台跳过、两项旧mini未在观察门内结束。本机默认editable指向旧工作树，固定本地src后两项在原时限下2pass/44.43秒；首次日志保留。最终固定源码完整门禁及双Python CI回执见第7节，不能把初跑写成全绿。

差分检查包括：

- 四规模、四压力场景的全部 starts/resource-wait/intentional-wait 与目标值。
- 小数资源/时长、容量容差、未来事件冲突、自身排除和不可行反例。
- 多地区/机器拓扑下全部迁移负载的逐值相等、完整候选顺序及抽样后的 RNG。
- 初始化所有父/trial 的候选流、种群与 Archive hash、exact 计数和后续 RNG。
- 固定工作量整程全部候选流、Population、Archive、Q 表、更新数、决策轨迹与每个子代的 RNG 快照。
- Archive 浮点并列、近容差点、外部成员列表修改、插入/尝试/峰值计数及缓存存活边界。
- 无候选、未接受轨迹只计算一次纯状态诊断，且保持原状态与 Q 更新。

固定工作量一致不表示等墙钟运行会逐步相同：更快的实现会在同一时间内处理更多子代，且原算法的探索率本来依赖时间进度。这不是算法规则变动；本轮也没有重跑等时间质量比较来宣称 HV 提升。

## 5. 内存与剩余热点

Archive 身份键缓存以额外内存换取少量重复量化；缓存只保留当前存活成员，不积累已淘汰候选。200任务的一个400时刻身份键，当前64位 Python 对新增量化整数和 tuple 的尺寸估算约16,104字节，不含字典/元组管理额外开销；若有1,584成员，单这些键约24.33MiB。这是构造例的对象尺寸估算，不是进程峰值实测。部署和调整并发前仍需真实内存验收，本轮没有服务器部署。

后续可继续研究 exact 中重复的可行性/区域功率事件扫描、A7/Compressible 的冻结日历复用，以及初始化构造后重复 SSGS 的完整 Schedule 传递。它们尚未实施；不能跳过最终独立 exact 或把浮点区间积分重排当成已证明无损。

本次没有修复综合13组的“唯一 trial 不足”失败，也没有自动续跑；修复该问题若涉及重复判定或候选生成规则，需要另行界定研究语义。

## 6. 本地复现

在该工作树根目录使用同一 Python 环境执行：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m pytest -q tests/test_performance_equivalence.py
python scripts/validate_all.py
python scripts/benchmark_core_performance.py --output outputs/performance-check --repeats 3
```

`benchmark.json` 保存每次 wall/CPU、汇总中位数和确定性摘要，摘要不一致直接失败。单模块 CPU 中位数不足0.05秒时不报告 CPU 比；三次重复仅为本机工程观察，不构造总体算法质量的置信结论。参考源码原样保存，`.gitattributes` 禁止改变其换行字节。
